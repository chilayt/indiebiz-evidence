# 独立合成验收规格（C-SPEC）

> 状态：**已冻结**（2026-11-10，基线 `1cac572`）
> 这份规格先于实现冻结，目的是让"预期结果"不来自被测代码。

## 这份验收证明什么、不证明什么

**证明**：在下面这些已定义的输入下，引擎的导入、查询、检测和 MCP 输出符合声明的语义。

**不证明**：
- 真实导出上的误报率（这需要真实语料，见 COMPLIANCE §六）
- 召回率
- 覆盖了全部规则（这八项是首批，不是全集）

**定性**：这是"实现之外的独立验收"，**不是第三方审计**——同一个维护者写了实现和验收。

## 冻结规则

1. **预期先于运行**：本文件的"必须核对的结果"在跑测试前写定，运行后不得修改以迎合输出。
2. **输入独立生成**：验收测试自己构造 CSV/JSON 文本，不调用生产代码的解析或检测辅助函数来计算预期。
3. **失败保留**：任何一项失败，保留红色结果和最小反例，另交修复补丁后再复验。不得靠调预期、放宽断言或删用例变绿。
4. **比较粒度**：精确到 `(source, entity 或 __schema__, 完整 kind 含字段名, observed_date)` 和字段值。只断言"出现了 value_swing"不算通过。
5. **全部虚构**：实体不存在，日期用 2099 年，不读取任何真实数据。

## 八个用例

### C01 缺失与零必须分开

输入：同一实体，某字段依次为 `10`、缺失（该字段不出现）、`0`。

必须核对：
- 中间那个捕获日**没有**该字段的事实行（不是 NULL 行、不是 0）
- 最后一天明确是数值 0
- `query_series` 的缺口就是缺席，不补零
- `search_records` 用 `field > 0` 过滤时，中间日不因"缺失"被当成 0 而排除或包含

### C02 告警必须落在正确的实体和字段上

输入：实体 A 价格 `10 → 40`，实体 B 价格保持 `10`，显式指定价格规则。

必须核对：
- `value_swing:price` 只出现在 **A** 上，日期是第二日
- B 上**没有**任何价格告警
- 告警的 detail 里能读到 10 和 40

### C03 身份边界不可跨越

输入：owner 从 `ALPHA` 变为 `ZULU`，变更当日价格缺失，下一次捕获价格大幅变化。

必须核对：
- `identity_change:owner` 可见
- **不得**跨边界计算价格涨跌（无 `value_swing:price`、无跨边界的百分比）
- 若输出 delta，必须明确标注跨身份边界

### C04 断档必须保留真实跨度

输入：先连续三天捕获，再间隔 30 天捕获。

必须核对：
- 变化说明里保留实际跨度（不是"隔一天"）
- 断档本身有可复核的依据（`gapped_transition` 或等价的显式说明）

### C05 空快照的三种含义必须分开

输入：
- (a) 新日期文件内容为 `[]`
- (b) 同一日期，把完整快照重导为 `[]`

必须核对：
- (a) 新日期**留痕**在时间轴上（批次存在，可查）
- (b) 重导为空**不得**留下旧事实（该日事实清空，或明确拒绝这种重导）
- 三种状态不得混为一谈：**成功导入的空快照**、**解析失败**、**没有采集**

> ⚠️ Codex 在本轮指出 (b) 当前**已经失败**（同日期重导为空会留下旧事实）。本项作为正式验收执行，失败即记录。

### C06 重导一致性

输入：同一日期把价格改为 `11` 并删除另一个字段，然后重复导入与检测。

必须核对：
- 没有旧字段残留
- 重复执行结果稳定（幂等）
- 本例**不要求**保存修订历史（那是后续探索项）

### C07 编码与来源可回溯

输入：GBK 编码导出、两个不同的中文实体、含中文和空格的路径。

必须核对：
- 两个实体**不合并**，值正确
- 能通过 `raw_ref` 回到输入文件并定位到对应记录

### C08 源隔离与错误语义

输入：名称相似的源（`shop` / `workshop`）分别导入；经 MCP 查询一个不存在的捕获日期。

必须核对：
- 结果不串源（各自时间轴独立）
- 不存在的日期**明确报错**，不能伪装成空快照返回 0 行
